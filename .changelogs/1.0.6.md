* Wawel Auth now only supplies skins and capes. Drawing them moved to Salamander: modern 64x64 skins with slim arms, flat and 3D skin layers, see-through skin pixels, and the related mod compatibility. Without Salamander, SimpleSkinBackport or Ears, skins are uploaded the way vanilla's model reads them
* With SimpleSkinBackport and without Salamander, slim arms from Wawel Auth's skins reach SimpleSkinBackport
* Without Salamander, SimpleSkinBackport or Ears, players without a skin are drawn as vanilla's Steve again, instead of a 64x64 Steve that vanilla's model draws stretched
* The skin layer settings moved to Salamander's config, which carries them over once
* Skin API version 2: the drawing types (skin layers, draw kinds, viewer settings) moved to Salamander's API
* Player heads given only a name find the server's own player of that name, online or recently seen, instead of a Mojang account of the same name; `name@provider` picks a player at a provider
* The server module is now off until `wawelAuthEnabled` is set in `server.json`, so a new server starts as a vanilla one instead of stopping for setup; servers whose `server.json` already enables it keep it on
* With the server module on, a server Wawel Auth can't run on (online-mode off, no `publicBaseUrl`) or a broken `server.json` now stops it cleanly before its world loads and says why, instead of exiting abruptly or crashing; clients no longer crash on a broken Wawel Auth config
* Fixed errors from ArmoredArms' outdated built-in Wawel Auth integration when equipping armor
* Fixed garbled skins on Model Citizens figures
* Player heads and offline accounts' local skins no longer read the account database or decode textures on every frame
* Addresses that Java refuses with "illegal IPv4 address" (such as a trailing dot or a part over 255) are now named in the log with the setting they come from and the reason, without showing the address
* When a server's advertised Wawel Auth address doesn't answer, as for players in the server's own network whose router doesn't loop the public address back, skins, logins and joins retry through the address the player joined with
* Launcher sessions from launchers that ship Ely.by's authlib, such as PineconeMC, and from authlib-injector set to a short address such as `ely.by` are now recognized and offered for import
* Imported launcher sessions are no longer refreshed or invalidated by Wawel Auth, which signed you out of the launcher; when one expires, the launcher's next session replaces it
* Accounts you sign into with a password in Wawel Auth are no longer overwritten by the launcher's session for the same account, which made them expire
* Servers without a chosen account now join with the account the launcher started the game with, when the server accepts it or doesn't run Wawel Auth, otherwise with the only account the server accepts, instead of failing with "No WawelAuth account active"
* Joining a server that has no account chosen and none to pick automatically, while you have accounts it accepts, first asks which one to join with; the choice is kept for that server
* Singleplayer worlds without a chosen account play as the account the launcher started the game with
* Each account now has its own inventory and position in a singleplayer world; before, every account got the world owner's player from level.dat
* Each singleplayer world can have its own account: the face at the right of a world shows the account it's played with, and clicking it picks the world's account and who may join it over LAN; shift-click it to drop the world's own account. Worlds without one use the account the launcher started the game with, or the singleplayer default if one was chosen before; shift-clicking the face of such a world stops it using that default, without changing other worlds
* The world creation screen has the same face beside the world name, to pick the account the new world is played with
* The Auth button at the top right of the server list, and the world list's Account button, are now Wawel Auth's logo, which opens the account manager. The button opening Wawel Auth's folder became the Menu at the bottom left of the account manager's preview, which also holds Config (Wawel Auth's Forge config, back to the account manager after), the cape creator, and Save skin and Save cape, which save the selected account's skin or cape to a file as it is, animated capes included
* With Salamander installed, the account manager's Menu has an entry that opens Salamander's expression editor on the selected account's skin; Back returns to the account manager. Other mods add such entries through `industries.angelic.wawelauth.api.gui.AccountPreviewButtons`, and `WawelAccounts.skinUploadEnabled` tells them whether an account's provider takes skin uploads, as the Upload Skin button shows
* Singleplayer worlds opened to LAN verify players with Wawel Auth's providers (Microsoft, Ely.by, LittleSkin and those a pack adds) and show everyone's skins, over LAN or relays such as e4mc. The world's account picker and the Open to LAN screen have a "LAN Access" list to pick the providers; a custom provider starts unticked. Players none of them verifies are turned away, unless the list lets them in as offline players as vanilla does
* Once a world is open to LAN, the pause menu's Open to LAN button becomes Manage LAN: the e4mc address with a button to copy it, the game mode and cheats of players who join from then on, LAN Access, and Stop LAN World, which sends joined players back with a message and also ends e4mc's session
* In a world open to LAN, players get commands when they join while cheats are on, and keep them until they leave, instead of everyone's commands following the cheats switch
* Wawel Auth no longer decodes Base64 with Java's own decoder, which Java 17.0.6 and later run as faulty machine code on processors with AVX-512 VBMI (CVE-2026-114938, "Java4Shell"); keys, signatures, textures and requests from servers, providers and players are decoded in plain Java. This doesn't protect other mods or Java itself: update Java, or start it with `-XX:-UseBASE64Intrinsics`
* Fixed joining a server through its Server Proxy failing with an error in real launchers, whose Minecraft 1.7.10 loads Mojang's blocked-server check
* Mojang's list of blocked servers, which launchers add to Minecraft 1.7.10, is no longer enforced; `enforceMojangBlockedServers` in the client config turns it back on
* New `importWithoutAsking` setting (`launcherimport` section of `wawelauth.cfg`) adds the launcher's account without asking, so modpack players can join servers that accept it without opening Wawel Auth
* Importing the launcher's account shows a toast with its face; clicking it opens the account manager on that account
* With Ely.by's authlib, which Legacy Launcher uses for Ely.by accounts, skins from Wawel Auth's providers show again instead of an Ely.by player's skin of the same name, and are checked like with the regular authlib. If a player still shows an Ely.by skin after updating, delete `.minecraft/assets/skins`
* Default provider files (`default-providers/*.json`) nobody edited now follow updates to the ones Wawel Auth ships; edited files are kept, with a note in the log
* Regular and Maven development jars now bundle runtime libraries; embedded-DepLoader builds use the `slim` suffix
* Fixed dark player skins in account and texture previews
* Isolated account previews from custom player-renderer state while retaining renderer-provided effects
* Fixed downstream development environments missing WawelAuth runtime libraries
* Fixed account previews crashing with the Forge and LiteLoader Chat Bubbles mods
* Added compatibility with FoamFix's modern skin renderer and standalone Ears, including local offline skins
* Fixed unreliable account-picker interactions and improved account-row hover feedback
* Picking an account in the account manager, or changing its skin or cape, no longer scrolls the account list back to the top
* The account manager opens about twice as fast the first time; the player preview appears a moment after the screen
* The account manager's preview shows a loading spinner while the player preview or the account's skin and cape load
* The account manager's preview shows Wawel Auth's logo, with the installed version on hover
* Animated capes now animate in the upload confirmation preview
* Animated PNG (APNG) capes: they play from any provider, such as Drasl, which serves them as plain PNGs, from offline accounts' cape files, and in the upload preview. Players without APNG support see their first frame
* Wawel Auth servers keep uploaded APNG capes animated, under the same limits as GIF capes, instead of saving them as still images, and say so in their API metadata
* Animated capes are kept at up to 512x256 per frame, so a long 2048x1024 cape no longer takes hundreds of MB of memory
* Cape creator, in the account manager's Menu, like minecraftcapes.net's animated cape creator: pick a GIF (or a still picture), an optional background cape, the color of the cape's sides, a size from 64x32 to 2048x1024 and whether the elytra shows the picture too, and watch it on the preview players. Save it to a file as an animated PNG or a GIF, set it on an offline account, or upload it where the account may upload capes: to a Wawel Auth server, within the size and animation it takes, or to another server such as Drasl, which says itself if it refuses the cape. Uploads are animated PNGs, except to older Wawel Auth servers, which keep only GIFs animated
* Wawel Auth servers now tell clients in their API metadata what texture uploads take: the largest skin and cape, the largest file, and whether and how large animated capes may be. Which textures a player may upload stays in the profile's `uploadableTextures` property
* The account manager's upload and reset buttons now follow what each provider says the account may upload, in the profile's `uploadableTextures` as authlib-injector specifies (Microsoft takes skins only), instead of config lists naming Ely.by, LittleSkin and Mojang. Drasl sends it from version 4. The disableSkinUpload, disableCapeUpload and disableTextureReset options now start empty, and only turn uploads off on top
* Fixed back-facing player previews appearing darker than front-facing previews
* Isolated skin-upload preview caches from account skins and cleaned up temporary preview textures on close
* Fixed server-list data loss from concurrent saves and stale snapshots, with atomic writes and protection against overwriting failed loads
* Players without a skin no longer get black marks on their face with Just Expressions or Fresh Moves: Wawel Auth's default Steve was black, not transparent, where no part of the skin shows, and those packs read some of it as eyes and brows
